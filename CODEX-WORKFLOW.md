# Как Работать С Codex На Проекте

Codex полезен не только чтобы "написать код", а чтобы думать как разработчик: объяснять, проверять, улучшать и планировать изменения.

## 1. Объяснить код

```text
Объясни файл app.py простыми словами. Я новичок. Сначала расскажи, что делает программа в целом, потом объясни основные функции.
```

## 2. Найти ошибки

```text
Проверь app.py как ревьюер. Найди реальные ошибки, слабые места и случаи, где программа может сломаться. Не переписывай код сразу, сначала объясни проблемы.
```

## 3. Улучшить одну часть

```text
Улучши только функцию save_lead в app.py. Не трогай остальной код. Цель: сделать проверки понятнее и не сломать текущую работу программы.
```

## 4. Попросить план перед кодом

```text
Я хочу добавить экспорт заявок в отдельный txt-отчет. Сначала составь короткий план изменения, какие функции затронуть и как проверить результат. Код пока не пиши.
```

## 5. Попросить тесты

```text
Предложи 5 ручных тестов для app.py: что ввести, что должно получиться и какую ошибку это проверяет.
```

## 6. Попросить README

```text
Улучши README.md так, чтобы проект выглядел как учебный портфолио-проект. Сохрани простой язык, без лишнего маркетинга.
```

## Правило

Не проси Codex "сделай все". Ставь маленькую конкретную задачу:

- какой файл;
- какую функцию;
- какой результат;
- что нельзя трогать;
- как проверить.

## Практика

Сегодня попроси Codex:

```text
Проверь app.py как наставник для новичка. Назови 3 вещи, которые уже сделаны хорошо, и 3 вещи, которые стоит улучшить дальше.
```
